# Post-Launch Retrospective

## What went well

- Weekly written updates kept stakeholders aligned
- Checkout testing caught an access issue before launch
- Clear ownership reduced duplicate work
- Launch-critical tasks were prioritized effectively

## What did not go well

- Video review started too late
- Copy approvals created downstream delays
- Some tasks had deadlines but no explicit acceptance criteria
- Last-minute changes created avoidable rework

## Root causes

1. Review checkpoints were scheduled too close to final delivery.
2. There was no formal content freeze.
3. Some deliverables were marked "done" before final QA.

## Improvements for the next launch

- Add first-cut video review earlier
- Introduce content freeze dates
- Require acceptance criteria on all launch-critical tasks
- Add explicit QA status separate from task completion
- Track revision rounds for creative deliverables
- Add a launch decision meeting 48 hours before release

## Metrics to carry forward

- On-time milestone completion
- Average revision rounds
- Number of blocker-level defects at launch
- Time spent waiting for approvals
- Launch revenue / enrollments
- Learner support issues in first 72 hours
